## 三、前置环境搭建教程

> ⚠️ 环境搭建是编程第一道坎，很多人在这里就放弃了。跟着下面的步骤走，5-30分钟搞定！

### 方案A：Dev-C++（推荐新手，5分钟搞定）

**优点**：下载安装即用，无需手动配置，自带编辑器和编译器
**缺点**：界面老旧，调试功能较弱，大学教学不常用

#### 安装步骤

**Step 1**：打开浏览器，访问 https://sourceforge.net/projects/orwelldevcpp/
> 这是 Dev-C++ 官方下载页，完全免费开源。

**Step 2**：点击绿色 "Download" 按钮，等待下载完成（约50MB）。

**Step 3**：双击下载的 `.exe` 文件，进入安装向导。
- 语言选择 **English**（原版更稳定，界面单词很少）
- 一路点 "Next"（下一步），使用默认设置
- 安装路径建议：`C:\Dev-Cpp`（不要有中文路径！）

**Step 4**：首次启动会弹出配置窗口，选择语言为 "简体中文"，字体建议选 "Consolas"（等宽字体，代码对齐漂亮）。

**Step 5**：测试是否成功：
1. `文件` → `新建` → `源代码`
2. 输入以下代码：

```c
#include <stdio.h>

int main() {
    printf("Hello, 我的第一个C程序！\n");
    return 0;
}
```

3. 按 `F11`（编译并运行）
4. 如果弹出黑窗口显示 `Hello, 我的第一个C程序！`，恭喜安装成功！🎉

#### Dev-C++ 常见问题修复

| 报错/问题 | 解决方案 |
|-----------|----------|
| 中文显示乱码 | 工具 → 编译器选项 → 设置 → 编译时加入以下命令：`-fexec-charset=GBK` |
| 编译后窗口一闪而过 | 在 `return 0;` 前加一行 `system("pause");` |
| 无法编译，提示 gcc.exe 错误 | 工具 → 编译器选项 → 检查编译器路径是否正确 |
| 背景/字体太小 | 工具 → 编辑器选项 → 字体，调大字号 |

### 方案B：VS Code + MinGW（推荐有追求的同学，30分钟）

**优点**：界面现代，插件丰富，大学和公司主流工具，调试功能强大
**缺点**：需要手动配置编译器路径，初次设置步骤较多

> 💡 **强烈建议走这个方案**，虽然初次配置麻烦，但 VS Code 是大学生和程序员的标准编辑器，早学早受益。而且网安学习写Python脚本也用同一个编辑器。

---

#### 第一步：安装 VS Code

1. 访问 https://code.visualstudio.com/ ，点击 "Download for Windows"
2. 双击安装包，一路下一步（**注意**：勾选"添加到 PATH"和"将 Code 打开操作添加到右键菜单"这两个选项！）

---

#### 第二步：安装 MinGW-w64 编译器

> MinGW 是 Windows 上的 GCC 编译器套装，让 Windows 也能编译 C 语言代码。

**方法1（官方，推荐）**：

1. 访问 https://winlibs.com/ （这是 MinGW 的便捷分发站）
2. 下载 `GCC x.x.x + LLVM/Clang ... Win64` 版本的 `.zip` 包（不带 MSVCRT 依赖的版本）
3. 将压缩包解压到 `C:\mingw64\`（**绝对不要有中文路径！！！**）
4. 记住编译器路径：`C:\mingw64\bin\gcc.exe`

**方法2（通过 MSYS2，更专业）**：

1. 访问 https://www.msys2.org/ ，下载安装 MSYS2
2. 安装后打开 MSYS2 终端（蓝色窗口），依次执行：
   ```bash
   pacman -Syu                          # 更新系统
   pacman -S mingw-w64-x86_64-gcc       # 安装64位GCC
   ```
3. 编译器路径在：`C:\msys64\mingw64\bin\gcc.exe`

---

#### 第三步：配置环境变量

1. 按 `Win + R`，输入 `sysdm.cpl`，回车
2. 点击"高级"选项卡 → "环境变量"
3. 在"系统变量"中找到 `Path`，双击编辑
4. 点击"新建"，输入编译器所在目录路径：
   - 如果是方案2方法1：`C:\mingw64\bin`
   - 如果是方案2方法2：`C:\msys64\mingw64\bin`
5. 点击确定保存所有窗口

**验证**：按 `Win + R`，输入 `cmd`，在黑色窗口输入：
```
gcc --version
```
如果看到类似 `gcc (x86_64-posix-seh-rev0) 14.x.x` 的输出，说明配置成功！

---

#### 第四步：VS Code 安装 C/C++ 插件

1. 打开 VS Code
2. 点击左侧竖排的"扩展"图标（或按 `Ctrl+Shift+X`）
3. 搜索并安装以下插件：
   - **C/C++**（微软出品，必装）
   - **C/C++ Extension Pack**（包含上面那个，更方便）
   - **Code Runner**（一键运行代码，可选）
   - **Chinese (Simplified) Language Pack**（中文界面，可选）

---

#### 第五步：写第一个C程序测试

1. 在桌面上新建文件夹 `C_Learning`（建议路径：`D:\C_Learning\`，不要用中文路径）
2. 打开 VS Code → `文件` → `打开文件夹` → 选择刚建的 `C_Learning`
3. 在左侧资源管理器右键 → `新建文件` → 命名为 `hello.c`
4. 输入以下代码：

```c
#include <stdio.h>

int main() {
    printf("Hello, C Language!\n");
    printf("你好，C语言！\n");
    return 0;
}
```

5. 按 `Ctrl + S` 保存
6. 按 `F5`（调试运行），选择 `C++ (GDB/LLDB)` → `gcc.exe`
7. 如果看到终端输出两行文字，恭喜你配置成功！🎉

---

#### VS Code 常见问题修复

| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `gcc : 无法将"gcc"项识别为 cmdlet...` | 环境变量没配好 | 回到第三步重新配置Path，确保路径指向 `bin` 文件夹 |
| `#include <stdio.h>` 下面有红色波浪线 | 插件没装或编译器路径未配置 | 安装 C/C++ 插件；按 `Ctrl+Shift+P` 搜索 `C/C++: Edit Configurations`，设置 compilerPath |
| F5调试报错 `launch: program ... does not exist` | 调试配置不正确 | 先 `Ctrl+S` 保存文件，再按F5 |
| 终端中文乱码 | 编码问题 | VS Code 右下角点击 `UTF-8` → `通过编码重新打开` → 选择 `GBK` |
| Code Runner 输出中文乱码 | 同上 | 设置中搜索 `code-runner.executorMap`，在 `c` 的编译命令后加 `-fexec-charset=GBK` |

## 五、自学避坑指南

> 以下8个坑，是无数C语言自学者血泪教训的总结。每一条都值得贴在你的书桌前。

### 🕳️ 坑1：只看视频不敲代码

**典型症状**：B站视频刷了30集，感觉都懂了，一打开编译器连 `main` 函数都写不对。

**为什么危险**：编程是"肌肉记忆"，不是"知识记忆"。就像学游泳，看100小时教学视频不下水，还是会淹死。

**正确做法**：视频和讲义时间 ≤ 总学习时间的30%。一天2小时学C，至少70分钟在敲代码。

---

### 🕳️ 坑2：跳过指针

**典型症状**：学到指针觉得难，想"先跳过，以后再说"。

**为什么危险**：指针是C语言的灵魂。不理解指针 = 不理解C = 不理解计算机怎么工作的。数据结构、操作系统、网络安全底层，全都绕不开指针。

**正确做法**：指针部分放慢速度，每天只学一个概念，多画内存图。Day 29-38会专门安排10天逐步攻克指针。

---

### 🕳️ 坑3：复制粘贴代码

**典型症状**：从讲义/网页直接Ctrl+C、Ctrl+V，觉得自己"看懂了就行"。

**为什么危险**：手打代码时，大脑在处理每一个字符，拼写错误、语法细节会进入潜意识。复制粘贴是"过眼不过脑"。

**正确做法**：对着讲义**逐行手打**。打错了更好！每次报错都是一次学习编译器的机会。

---

### 🕳️ 坑4：不读报错信息

**典型症状**：代码出错，只看第一行红色字，然后直接问别人"为什么错了"。

**为什么危险**：读报错是程序员的核心能力。编译器已经告诉你错在哪一行、什么类型错误，不学会读报错 = 永远依赖别人。

**正确做法**：报错三步法：
1. 看错误类型（error还是warning）
2. 看行号（定位到具体代码行）
3. 查 [appendix-b-编译报错大全.md](appendix-b-编译报错大全.md) 找对应解决方案

**至少自己调试10分钟**，实在解决不了再问人。

---

### 🕳️ 坑5：贪多嚼不烂

**典型症状**：一天学3天的内容，觉得"进度太慢"。

**为什么危险**：C语言知识点环环相扣。Day 8的循环学了但Day 5的运算符没搞透 → 写出来的循环条件都是错的 → 越学越懵 → 放弃。

**正确做法**：严格按60天节奏走。如果某天内容提前学完，就多做题、多敲代码，而不是赶进度。每一层通关标准达到后再进下一层。

---

### 🕳️ 坑6：忽视代码规范

**典型症状**：变量名随便起（`a`、`b`、`x1`、`x2`），缩进混乱，从不加注释。

**为什么危险**：坏习惯一旦形成非常难改。大学的编程作业、竞赛代码评审，代码风格都是评分项。工作时同事看不懂你的代码更麻烦。

**正确做法**：从 Day 1 就养成好习惯：
- 变量名有意义：`studentScore` 而不是 `s`
- 缩进整齐：大括号对齐，`if` 内部缩进4格
- 关键代码加注释：不是每行都注，但关键逻辑要说明

---

### 🕳️ 坑7：害怕报错和Bug

**典型症状**：一出错就沮丧，觉得自己不适合学编程。

**为什么危险**：编程 = 写Bug → 找Bug → 改Bug → 出新Bug → 再改...循环往复。即使是工作10年的程序员，每天也在和报错打交道。报错不是失败，是学习的入口。

**正确做法**：心态调整——每次报错都在告诉你"这东西不是这么用的"，这是编译器在免费教你。把报错记入每日打卡表的"报错记录区"，积累自己的排错经验库。

### 🕳️ 坑8：英文文档恐惧症

**典型症状**：看到英文技术文档就关掉，只搜中文教程。

**为什么危险**：最新的技术文档、API手册、开源项目全部是英文的。中文翻译往往滞后2-3年，而且翻译质量参差不齐。

**你的优势**：高考英语135分，阅读英文技术文档完全够用。C语言的英文文档词汇量其实很小，反复出现的就那200个词（如 variable, function, pointer, array, memory, allocate...）。坚持读两周就全认识了。

**正确做法**：module-6 中有"英语编程术语每日精读计划"，利用你的英语优势，比同龄人更快接触一手技术资料。
