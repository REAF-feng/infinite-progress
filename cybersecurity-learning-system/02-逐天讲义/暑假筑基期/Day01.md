## 📖 通俗理论讲解

### 1.1 计算机 = 一个超级听话的计算器

从本质上看，计算机**只会做一件事：计算**。

你点开一个网页、播放一首歌、打开一篇Word文档——背后统统是在做"加法运算"。只不过计算机做得太快了（每秒几十亿次），快到你以为它在"放音乐"。

**生活类比**：计算机就像一个只会做菜的厨师：
- 你给它菜谱（程序）和食材（数据）
- 它按菜谱一步步做
- 最终给你端出成品（结果）

计算机没有"理解"能力——它只是在忠实地执行指令。让它算1+1，它就算1+1。它不知道"1"是什么含义，它只是按规则把两个数加起来。

---

### 1.2 计算机的五大组成部分（冯·诺依曼架构）

1945年，数学家冯·诺依曼提出了一个计算机结构模型，至今所有计算机（包括你的手机）都遵循这个模型。它把计算机分成5个部分：

```
           ┌──────────────┐
           │   控制器(CU)  │ ← 指挥中心："下一个步骤是啥？"
           │   ┌──────┐    │
           │   │指令  │    │
           │   │寄存器│    │
           │   └──────┘    │
           └──┬───────┬───┘
              │       │
     控制信号 │       │ 控制信号
              │       │
    ┌─────────▼──┐ ┌─▼──────────┐    ┌──────────────┐
    │  运算器(ALU)│ │  控制器(CU) │    │   输出设备    │
    │  负责计算   │ │  负责指挥   │    │ 显示器/打印机 │
    └─────────▲──┘ └─▲──────────┘    └──────▲───────┘
              │       │                      │
              │       │                      │
         ┌────┴───────┴──────────────────────┴─┐
         │             总线(Bus)                │
         │   = 各部分之间的"数据高速公路"        │
         └──┬──────────────────────────────┬───┘
            │                              │
    ┌───────▼────────┐          ┌──────────▼──────┐
    │   存储器(内存)  │          │   输入设备       │
    │  正在用的数据   │          │ 键盘/鼠标/网卡   │
    │  断电数据消失   │          └─────────────────┘
    └────────────────┘
```

#### 用厨房做菜类比五大部件：

| 计算机部件 | 厨房类比 | 解释 |
|-----------|---------|------|
| **运算器（ALU）** | 厨师的手 | 真正动手干活的人——切菜、翻炒、调味 |
| **控制器（CU）** | 厨师的大脑 | 看菜谱、决定下一步做什么 |
| **存储器（内存）** | 厨房操作台 | 放正在处理的食材——空间有限，做完一道菜就收走（关机数据消失） |
| **输入设备** | 买菜/进货 | 把数据"输入"到计算机——键盘打字、鼠标点击、网线传数据 |
| **输出设备** | 上菜/出餐 | 把结果"输出"给你看——显示器显示、打印机打印 |

> ⚠️ 注意：CPU = 运算器 + 控制器。这两个合在一起叫"中央处理器"（CPU），是计算机的"大脑"。

### 1.3 程序是怎么运行的？——一个完整的故事

假设你在Windows上双击了一个软件图标。以下是从头到尾发生的一切：

```
第1步：你双击图标
      → 操作系统（Windows）知道你要打开这个程序

第2步：从硬盘加载到内存
      → 硬盘 = 冰箱（永久存放、容量大、速度慢）
      → 内存 = 操作台（临时放置、容量小、速度快）
      → 操作系统把程序文件从硬盘"搬"到内存中
      → 为什么？因为CPU只能直接和内存"对话"，不能直接读硬盘

第3步：CPU开始工作
      → CPU从内存中读取第一条指令
      → 执行这条指令（比如："把这个数加1"）
      → 再读取下一条指令
      → 再执行……
      → 这就是"取指令→执行→取指令→执行"的循环
      → 每秒几十亿次，所以你觉得电脑很快

第4步：输出结果
      → CPU执行完，把结果写回内存
      → 操作系统把结果显示到屏幕上
```

**关键理解**：CPU从来不"看"硬盘。数据必须先从硬盘搬到内存，CPU才能处理。这就是为什么：
- 你的电脑内存越大，软件开得越多
- 硬盘换成SSD（固态硬盘）后开机变快——因为搬运速度变快了

### 1.4 二进制：为什么计算机只认识0和1？

计算机底层只理解两种状态：**通电（1）和不通电（0）**。

**类比**：就像电灯开关——要么开，要么关，没有"半开"。

那怎么表示复杂的东西呢？——**用多个0和1组合**：

```
1个灯泡（1位）：  0 或 1                       → 2种可能
2个灯泡（2位）：  00, 01, 10, 11              → 4种可能
3个灯泡（3位）：  000, 001, 010, 011,          → 8种可能
                  100, 101, 110, 111
8个灯泡（8位）：  2^8 = 256种可能               → 这就是1个"字节(Byte)"

101 = 1×4 + 0×2 + 1×1 = 5（十进制）
110 = 1×4 + 1×2 + 0×1 = 6（十进制）
```

**为什么安全工程师要懂这个？**
- IP地址本质上是32个0/1（IPv4）或128个0/1（IPv6）
- 密码学里的密钥是二进制数据
- 分析恶意软件时经常要读"十六进制"（Hex）——它就是二进制的"缩写"

## 🔧 实操环节

### 实操目标
在Kali Linux虚拟机中查看计算机硬件配置。

### 步骤

#### 1. 启动虚拟机并打开终端

```
启动Kali Linux虚拟机 → 登录 → 打开终端
（如果忘了怎么操作，回顾环境搭建教程第四部分）
```

#### 2. 查看CPU信息

```bash
lscpu
# 命令：lscpu = list CPU（列出CPU信息）
# 作用：查看虚拟机的CPU信息
# 不需要sudo，普通用户就能执行
```

你会看到类似这样的输出：
```
Architecture:        x86_64          ← 架构（x86_64表示64位CPU）
CPU(s):              2               ← 你分配了几个CPU核心
Model name:          Intel(R) Core(TM) i5-xxxx
CPU MHz:             2400.000        ← CPU主频（速度）
```

**重点看**：`CPU(s): 2` ——这个数字是你在VMware里分配的CPU核心数。

#### 3. 查看内存信息

```bash
free -h
# 命令：free = 显示内存使用情况
# 参数：-h = human-readable（人类可读，自动转换单位）
# 作用：看看虚拟机的内存有多大、用了多少
```

你会看到：
```
              total        used        free      shared  buff/cache   available
Mem:          1.9Gi        562Mi       1.2Gi       5.0Mi       198Mi       1.3Gi
Swap:            0B          0B          0B
# Mem = 内存（total=总大小, used=已用, free=空闲）
# Gi = Gibibyte（≈GB），Mi = Mebibyte（≈MB）
# 你的total跟你在VMware里设置的内存大小一致
```

#### 4. 查看硬盘信息

```bash
df -h
# 命令：df = disk free（显示磁盘剩余空间）
# 参数：-h = human-readable
# 作用：看看虚拟机的硬盘有多大、还剩多少空间
```

你会看到类似：
```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        80G  8.0G   68G  11% /
# Size=总大小, Used=已用, Avail=可用, Use%=使用百分比
# /dev/sda1 是你的虚拟硬盘
# / 是根目录——整个文件系统的起点
```
