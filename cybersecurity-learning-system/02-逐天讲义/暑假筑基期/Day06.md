## 📖 通俗理论讲解

### 6.1 为什么需要多用户和权限？

计算机不是只有你一个人在用：
- 服务器上有网站管理员、数据库管理员、普通用户
- 你的电脑上，操作系统本身也有很多"虚拟用户"在运行服务

**如果不控制权限会发生什么？**
- 网站访客可以把网站源码删了
- 一个程序崩溃能搞垮整个系统
- 电脑中病毒后，病毒可以修改一切

**类比：公寓大楼**
```
root（超级管理员）= 大楼主人——有所有房间的钥匙，可以改任何东西
普通用户 = 租客——只有自己房间的钥匙，不能进别人房间
系统用户 = 物业维修工——只负责自己管的那一块（修水电的不能改门禁系统）
```

---

### 6.2 rwx在不同场景下的含义

昨天学了r=读、w=写、x=执行。但它们对文件和目录的含义不同：

| 权限 | 对文件 | 对目录 |
|------|--------|--------|
| **r**（读） | 可以看文件内容（cat file） | 可以列出目录内容（ls dir） |
| **w**（写） | 可以修改文件内容 | 可以在目录里创建/删除文件 |
| **x**（执行） | 可以运行这个程序 | 可以cd进入这个目录 |

**一个常见陷阱**：你有目录的r权限但没x权限？
```
→ 你能ls看到文件名，但cd不进去！
→ 就像你能透过窗户看房间里有啥，但没钥匙进门
→ 所以目录的x权限极其重要，没有它等于"不能访问该目录"
```

---

### 6.3 sudo是什么？

Linux默认你是一个普通用户（kali），不能修改系统文件、不能安装软件——这保证了安全性。

当你需要做"管理员级别"的操作时，在前面加 `sudo`：

```bash
apt install python3
# 权限不够，会报错！

sudo apt install python3
# sudo = Super User DO（以超级用户的身份执行）
# 系统会提示输入密码（就是你的kali密码）
# 然后以管理员权限执行后面的命令
```

**类比**：sudo = 借大楼主人的钥匙用一下，用完就还。你不是主人，但你临时有了主人的权限。

## 🔧 实操环节

### 实操1：查看用户信息

```bash
# 查看当前用户
whoami
id
# id显示更多信息：用户ID(uid)、组ID(gid)、所属组

# 查看系统中的所有用户
cat /etc/passwd
# 每行一个用户，格式：用户名:x:UID:GID:描述:家目录:Shell
# 别紧张！大部分是系统用户（运行各种服务的），不是你创建的

# 只看"真人"用户（UID >= 1000）
awk -F: '$3>=1000' /etc/passwd
# awk -F: 用冒号分割每行
# $3>=1000 只打印第三列(UID)大于等于1000的行
```

### 实操2：理解文件权限——动手实验

```bash
cd ~/cybersec-practice

# 创建一个脚本文件
echo '#!/bin/bash' > test.sh
echo 'echo "This script runs!"' >> test.sh
# 这是一个简单的Bash脚本（Shell脚本）

cat test.sh
# 查看内容

# 尝试运行它
./test.sh
# 报错：bash: ./test.sh: Permission denied
# 为什么？因为test.sh没有执行权限(x)

ls -l test.sh
# 输出：-rw-r--r-- ... test.sh
#      看第一个"-"后面"rw-"——属主只有读写，没有执行

# 赋予执行权限
chmod +x test.sh
# chmod = change mode（修改权限）
# +x = add execute（增加执行权限）
# 给属主、属组、其他人都加上了x

ls -l test.sh
# 输出：-rwxr-xr-x ... test.sh
#      现在有x了！

./test.sh
# 输出：This script runs!
# 成功了！
```

### 实操3：chmod数字法——精准控制权限

数字法更精准，一次设好所有权限：

```bash
# 创建一个测试文件
touch perm-demo.txt
ls -l perm-demo.txt
# 默认权限：-rw-r--r-- （属主读写、其他人只读）

# 数字法：三个数字分别代表 属主 属组 其他人
# r=4, w=2, x=1，加起来

chmod 644 perm-demo.txt
# 6=4+2（rw-）：属主可读写
# 4（r--）：属组只读
# 4（r--）：其他人只读
# 这是文件的"标准权限"

chmod 755 perm-demo.txt
# 7=4+2+1（rwx）：属主全部权限
# 5=4+1（r-x）：属组读+执行
# 5=4+1（r-x）：其他人读+执行
# 这是可执行脚本的"标准权限"

chmod 777 perm-demo.txt
# 所有人都有全部权限！
# ⚠️ 这是最危险的权限设置——任何人都可以读、写、执行！
# 永远不要在生产环境用777！
```

**常用chmod数字速记：**

| 数字 | 权限 | 使用场景 |
|------|------|----------|
| 644 | rw-r--r-- | 普通文件（自己能改，别人只能看） |
| 755 | rwxr-xr-x | 脚本/程序（自己能改能运行，别人能运行） |
| 600 | rw------- | 私密文件（只有自己能读写） |
| 700 | rwx------ | 私密脚本（只有自己能访问） |
| 777 | rwxrwxrwx | ⚠️永远别用！ |

### 实操4：sudo实战

```bash
# 更新软件包列表（需要管理员权限）
sudo apt update
# 输入你的kali密码（屏幕不显示，正常输入就行）
# 这个命令会从Kali软件源下载最新的软件包列表

# 查看/var/log目录（存放系统日志，普通用户可能没权限直接进入）
ls /var/log
# 应该能看到，但有些日志文件你看不了内容

sudo cat /var/log/syslog
# syslog是系统主日志，必须用sudo读
# 内容很多，按Ctrl+C可以中断

# ⚠️ sudo的使用原则：
# 1. 只在必要时用sudo（不要sudo ls这种没必要的）
# 2. 执行前确认命令正确（sudo rm -rf / = 灾难）
# 3. 不要复制粘贴网上找到的sudo命令——先理解再执行
```

## 📋 今日知识点总结

| 编号 | 知识点 | 说明 |
|------|--------|------|
| 1 | 用户类型 | root(超级管理员)、普通用户、系统用户 |
