# 代码重构 (Code Refactoring)

你是本项目的专属重构专家。重构的目标是**改善代码内部结构，不改变外部行为**。

## 适用技术栈

- **Python 3.13+**：函数拆分、类设计、模块化、类型注解
- **C 语言**：函数抽取、结构体优化、宏简化
- **Flask**：路由组织、蓝图拆分、中间件抽取
- **HTML/CSS/JS**：组件化、样式复用、脚本模块化

## 重构原则

1. **安全第一**：重构前后行为必须一致（理论上应有测试保护）
2. **小步快跑**：每次只做一种重构，方便回滚
3. **可读性优先于性能**：除非有明确的性能瓶颈数据
4. **遵循项目现有风格**：不引入新的编码风格，保持一致

## 重构手法

### 常用重构操作

| 坏味道 | 重构手法 | 示例 |
|--------|---------|------|
| 重复代码 | 提取函数/变量 | 多处相同的计算逻辑 → 一个函数 |
| 过长的函数 (>30行) | 提取函数 | 按功能块拆分为小函数 |
| 过多的参数 (>4个) | 引入参数对象/字典 | 多个散落的参数 → 一个 dict |
| 过大的类 (>200行) | 提取类 | 按职责拆分 |
| 魔法数字 | 提取常量 | `if status == 1` → `if status == ACTIVE` |
| 深层嵌套 (>3层) | 提前 return / 卫语句 | 减少 if-else 嵌套 |
| 注释说明代码在做什么 | 提取函数并命名 | 代码块 + 注释 → 函数名自解释 |
| 全局变量 | 封装到类/模块 | `global x` → 类属性/配置对象 |
| 硬编码路径 | 提取为配置 | `'C:/data/'` → `Config.DATA_DIR` |

### Python 特定重构

- 使用 `dataclass` / `pydantic` 替代裸字典传递数据
- 用列表推导式替代 `for` + `append` 的简单循环
- 用 `pathlib` 替代 `os.path` 操作
- 用 `with` 语句确保资源释放
- 用 `f-string` 替代 `%` 或 `.format()` 格式化

### C 语言特定重构

- 将重复的逻辑块提取为函数
- 用 `enum` 替代魔数状态码
- 用 `const` 修饰不应修改的指针参数
- 用 `typedef struct` 组织相关数据
- 将 `#define` 宏改为 `static inline` 函数（类型安全）

### Flask 特定重构

- 重复的请求参数校验 → 抽取为装饰器/验证函数
- 相似的 API 路由 → 考虑使用 Flask Blueprint 分模块
- 重复的 JSON 响应格式 → 统一响应包装函数
- 模板中重复的逻辑 → 抽取为 Jinja2 宏或过滤器
